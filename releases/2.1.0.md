## Arches Modular Reports 2.1.0 Release Notes

### New Features

- Replace the default report with a new design: Report, Data and Graph workspaces, with edits queued in an edit list and saved together [#PR](https://github.com/archesproject/arches-modular-reports/pull/PR)
- Add Edit History, Images, Related Resources and Manage panels to the report [#PR](https://github.com/archesproject/arches-modular-reports/pull/PR)
- Add `--slug` to `report_configs generate` and validate configs before saving [#PR](https://github.com/archesproject/arches-modular-reports/pull/PR)

### Bug fixes

### Breaking changes

- Arches 8.2.0 is now the minimum Arches version [#198](https://github.com/archesproject/arches-modular-reports/pull/198)
- `arches_querysets` and `arches_vue_components` now ship inside arches as `arches.extensions.querysets` and `arches.extensions.vue_components`, so they are no longer separate `pip install`/`npm install` dependencies. Uninstall the standalone packages and update `INSTALLED_APPS` and any `include()` of their urls to the new module paths [archesproject/arches#12933](https://github.com/archesproject/arches/pull/12933)
- The `ReportHeader`, `ReportToolbar`, `ReportTombstone`, `ReportTabs`, `LinkedSections` and `RelatedResourcesSection` components and the resource editor are removed. Regenerate default report configs (see below) [#PR](https://github.com/archesproject/arches-modular-reports/pull/PR)
- The `api_modular_reports_resource`, `api_modular_reports_blank_tile`, `api_node_tile_data`, `api_related_resources` and `api_client_language_settings` endpoints and their frontend helpers are removed [#PR](https://github.com/archesproject/arches-modular-reports/pull/PR)

### Upgrading Arches Modular Reports

1. Upgrade python package

    ```bash
    pip install --upgrade arches-modular-reports==2.1.0
    ```

1. Uninstall the packages now bundled with arches, so the bundled copies are the ones that load:

    ```bash
    pip uninstall arches-querysets arches-vue-components
    ```

1. Ensure `pgtrigger` is listed in your project's `INSTALLED_APPS` alongside `arches_modular_reports`, `arches.extensions.querysets`, and `arches.extensions.vue_components`, and that any `include()` of their urls uses the same paths. The old top-level module paths still resolve in Arches 8.2 but raise a `DeprecationWarning` and are removed in Arches 9.0.

1. Remove `"arches-vue-components"` from your project's `package.json` dependencies — its frontend now ships with arches — then reinstall your frontend dependencies:

    ```bash
    rm -r node_modules; rm package-lock.json
    npm install
    ```

1. Run migrations

    ```bash
    python manage.py migrate
    ```

1. Regenerate default report configs (this overwrites any edits to them):

    ```bash
    python manage.py report_configs generate --slug default --overwrite
    ```

1. Update webpack build

    ```bash
    npm run build_development
    python manage.py collectstatic
    ```

1. If you are running Arches on Apache, restart your server:

    ```bash
    sudo service apache2 reload
    ```
